# 🥗 Nutri — трекер питания, БЖУ и веса

Приложение для похудения / поддержания / набора массы. React + TypeScript + Vite + Tailwind.

## Что умеет

- **Цель задаёт норму.** Пол, возраст, рост, стартовый вес и активность → BMR (Миффлин–Сан Жеор) и TDEE; вес для расчёта — последнее взвешивание. Изменение поля «Вес, кг» в параметрах профиля сразу пересчитывает норму по формуле и сохраняет взвешивание за сегодня; прошлые взвешивания не меняются. В ручном режиме БЖУ остаются фиксированными до нажатия «↺ По цели». Цель — базовая норма, пока БЖУ не заданы руками: **похудение** — калории на 20% ниже TDEE, белок 2,2 г/кг; **поддержание** — на уровне TDEE, белок 1,8 г/кг; **набор массы** — на 10% выше TDEE, белок 1,8 г/кг. Калории при похудении не опускаются ниже BMR. Жиры — 30% калорий, углеводы — остаток. Норму белков, жиров и углеводов можно задать руками: тогда она важнее цели, а смена цели спрашивает подтверждение. Калории считаются из БЖУ (белки и углеводы по 4 ккал/г, жиры по 9 ккал/г).
- **Дневник по дням.** Приёмы пищи со **своим временем** (Завтрак 08:30, Обед 13:30 и т.д.), продукты с граммовкой, кольцо калорий и полосы БЖУ.
- **Календарь питания: копирование месяца.** Сам календарь не изменился: сетка дней, ‹ › для перехода по месяцам и легенда. Под ней — кнопка «📋 Скопировать за ноябрь 2026»: весь открытый месяц уходит в буфер обмена обычным текстом, день за днём, с днём недели и датой («понедельник, 2 ноября 2026 — 452 ккал · Б 41 г · Ж 14 г · У 43 г»), а если включена галочка «С продуктами и граммовками» — ещё приёмы пищи и каждый продукт с граммовкой. Внизу текста — «Всего за период», число дней с записями, среднее в день и список дней без записей. Чтобы скопировать прошлый месяц, переключи месяц стрелкой ‹.
- **Рацион дня текстом.** Под карточкой дня — кнопка «📋 Скопировать рацион»: день целиком уходит в буфер обмена обычным текстом, который можно вставить в сообщение или отправить тренеру. В тексте — дата, **норма БЖУ из настроек профиля** («Норма в день: 2180 ккал · белки 154 г · жиры 73 г · углеводы 240 г»), съедено за день, остаток до нормы (и отдельная строка «Перебор», если он есть), затем приёмы пищи по времени с продуктами и граммовками.
- **Заметки по дням.** Кнопка «📝 Заметки» открывает поле для личных записей к выбранной дате. Текст сохраняется автоматически отдельно для каждого дня и входит в экспорт/импорт данных. В том же окне есть простой калькулятор (+, −, ×, ÷), результат можно вставить в заметку.
- **Меню приёма «⋮».** В шапке карточки приёма — одна кнопка «⋮»: «Дублировать приём», «Скопировать приём на завтра» и «Удалить приём» (с подтверждением). Крошечные значки со стрелками и крестиком убраны.
- **Жесты на продукте.** Свайп влево — «Удалить» (с подтверждением: сначала спросит, что именно убрать), свайп вправо — «На завтра»: копия продукта уходит в корзину следующего дня, в калории дня она не идёт, пока не окажется в приёме. Долгий тап — перенос в другой приём, тап — изменить граммовку.
- **Корзина дня.** Кнопка 🧺 появляется, когда на просматриваемый день перенесены продукты: их видно списком со счётчиком. Продукт зажимают пальцем и перетаскивают в нужную карточку приёма — карточка подсвечивается, продукт встаёт в конец списка (в калории дня он попадает именно в этот момент). Неперетащенные продукты лежат в корзине своего дня и через месяц автоматически вычищаются.
- **Скан штрихкода.** Сканирование доступно внутри «+ Добавить продукт»: открой нужный приём, нажми кнопку камеры рядом с поиском, и откроется сканер (нативный BarcodeDetector + ZXing). Штрихкод, QR или DataMatrix с номером товара → карточка подставляется из своей базы или Open Food Facts. Не нашлось — открывается ручная карточка с уже подставленным кодом.
- **Поиск по названию.** Недавние и своя база + онлайн-поиск Open Food Facts; найденное сохраняется в базу. Запрос ищется **по словам в любом порядке** с учётом «ё/ъ» и опечаток («сырный соус махеев» → «Соус майонезный Сырный 50.5%» «Махеевъ»), штрихкод можно вводить цифрами. Неточное совпадение помечается «ниже похожие продукты». Если штрихкод привёл не к тому соусу, в карточке порции можно обновить данные по коду или найти продукт по названию с упаковки — онлайн-карточка сохранится в базу и заменит старую запись с тем же штрихкодом.
- **База продуктов.** 232 позиции в комплекте (65 базовых + 167 брендовых, включая полку соусов «Магнит»: «Махеевъ» Сырный/Цезарь/Сливочно-чесночный/Сметанный с грибами/Тар-тар/Бургер, Heinz, Слобода, Astoria, Mr. Ricco, Pikador, кетчупы и майонез; зефир «Бело-розовый» Сокол с ванилью и малиной; гречку/рис/макароны с полки «Магнит» — Макфа, Шебекинские, Увелка, Националь, Мистраль и СТМ «Магнит», в том числе гречку 1 сорт) + свои и найденные онлайн; поиск, редактирование, удаление. У части брендовых позиций есть **проверенный штрихкод** — сканер находит их мгновенно и без интернета. Если в онлайн-карточке есть БЖУ, но нет калорий, приложение рассчитывает ккал из белков, жиров и углеводов; если БЖУ нет совсем, приложение не выдаёт пустую карточку за готовые данные, а открывает форму с подставленным названием.
- **Норма БЖУ в настройках — ручной ввод.** В карточке «Норма калорий и БЖУ» у белков, жиров и углеводов стоят кнопки «−» и «+»: одно нажатие меняет цифру на шаг (белки ±10, жиры ±5, углеводы ±100 г), а саму цифру можно вписать с клавиатуры. Калории пересчитываются из БЖУ на лету и показываются тут же. Темп (кг/нед) и слайдер «Ручная корректировка» калорий убраны полностью — вся подстройка нормы здесь. Кнопка «↺ По цели» возвращает норму, рассчитанную по выбранной цели (она активна, только когда БЖУ заданы руками). У профилей, сохранившихся от прежней версии, норма один раз замораживается в ручные БЖУ — цифры не «прыгают» после обновления.
- **Компактный профиль.** Сверху всегда видна норма на день: калории, белки, жиры, углеводы и режим «По формуле / Вручную». «Изменить» открывает настройки, «Готово» снова защищает их от случайной правки. Возраст, рост и вес стоят в одной выровненной сетке с короткими подписями и одинаковыми полями. Пол и цель выбираются компактными кнопками, активность — списком. Формула, BMR/TDEE и шаги БЖУ спрятаны под «Как считается норма». В «Моих данных» — сохранение/загрузка копии и копирование продуктов; сброс вынесен в отдельный раскрываемый раздел с подтверждением. Функции и сохранённые данные не меняются.
- **Компактные настройки.** Активность выбирается выпадающим списком с подсказками, поля «Возраст/Рост/Вес» — компактные, кнопки данных (сохранить/загрузить/сбросить) в одну строку.
- **Выпадающий список раскрывается вниз.** «Активность» в настройках раскрывается всегда вниз от своего поля, на всю его ширину и плавно. Если поля мало внизу экрана, страница чуть подкручивается, чтобы пункты поместились, — вверх список больше не «переворачивается».
- **График веса без настройки периода.** В «Прогрессе» всегда показан компактный график за последние пять календарных месяцев: период двигается автоматически с текущей датой и новыми взвешиваниями. Переключателей «Неделя / Месяц / Год» больше нет, поэтому при возвращении на вкладку нечему сбрасываться. Фиолетовые точки — фактические взвешивания, расстояния между ними соответствуют времени. Если записей за последние пять месяцев нет, автоматически показывается пятимесячное окно до последнего взвешивания с пояснением. Старые записи остаются в истории и экспорте, но не растягивают график. Одно взвешивание отображается точкой; линия появляется после второго. Средние калории и белок считаются за тот же период, что и график.
- **Приложение с домашнего экрана (PWA).** Манифест, иконки и service worker; на iPhone можно «Поделиться → На экран Домой» и открывать как обычное приложение. Нижняя безопасная зона футера ограничена реальной высотой индикатора «домой», а сплошной фон навигации заполняет эту зону без дополнительной полосы под футером.
- **Мои продукты текстом.** В настройках (вкладка «Профиль» → карточка «Данные») — кнопка «📋 Скопировать мои продукты (N)»: в буфер обмена уходит список только своих продуктов — введённых вручную и найденных онлайн/по штрихкоду, без встроенной базы из 232 позиций. По одному на строку и по алфавиту: название, бренд (если указан) и БЖУ на 100 г («Горох колотый — 331 ккал · Б 23 г · Ж 1,5 г · У 62 г»). Штрихкод и порция в текст не попадают. Пока своих продуктов нет, кнопка неактивна и под ней — подсказка, откуда они берутся.
- **Данные локально** (localStorage), есть экспорт/импорт JSON.


## Разработка и проверки

Требуется **Node.js 24** (версия закреплена в `.nvmrc`, `package.json` и CI).

```sh
nvm use
npm ci
npm run dev
npm run check       # TypeScript + тесты + production-сборка
npm run build:pages # однофайловая сборка и обновление docs/
```

Обычная сборка `npm run build` использует разделение кода: график и сканер загружаются по запросу. Для GitHub Pages сохраняется однофайловая сборка. Service worker не кэширует ресурсы: установка PWA не гарантирует офлайн-запуск.

### Сохранность данных

- Импорт проверяет профиль, продукты, приёмы пищи и взвешивания **до** замены состояния. Некорректный файл не заменяет дневник.
- При обнаружении повреждённых данных localStorage исходная строка резервируется в `nutri-tracker-v1-recovery` до очистки. Это аварийная копия внутри того же браузера, а не замена экспорту JSON.
- Если чтение невозможно, автосохранение блокируется до перезагрузки, чтобы не затереть исходную запись. При ошибке записи приложение показывает предупреждение: нужно экспортировать данные, пока вкладка открыта.
- В режиме «По цели» вес меняет белок и энергозатраты; рост, возраст, пол и активность меняют энергозатраты, жиры и углеводы. Белок рассчитывается по весу и цели, поэтому не обязан меняться при изменении роста или возраста. Возможны одинаковые округлённые значения при небольших изменениях параметров.
- Повторный выбор текущей цели при ручных БЖУ также предлагает вернуться к формуле с подтверждением.

## Деплой на Vercel (рекомендуется)

Репозиторий уже настроен: `vercel.json` (framework `vite`, build `npm run build`, output `dist`, SPA-rewrites, `Permissions-Policy: camera=(self)`).

1. Открыть **https://vercel.com/new** и войти через GitHub
2. **Import** репозитория `Aistben/TrackerGym3` (при первом разе — Add GitHub Account / Configure и дать доступ к репо)
3. Настройки подставятся сами из `vercel.json` → **Deploy**
4. Через ~1 минуту будет адрес вида `https://tracker-gym3.vercel.app`

Какая ветка уходит в прод:
- слить PR с изменениями в `main` — прод собирается с `main`;
- либо **Project → Settings → Git → Production Branch** поставить `main`.

Каждый пуш в ветку = автоматический новый деплой, плюс preview-ссылка на каждый PR.

## Открыть с телефона (постоянная ссылка)

В репозитории лежит готовая однофайловая сборка `docs/index.html`. Чтобы получить постоянный HTTPS-адрес:

1. GitHub → репозиторий → **Settings → Pages**
2. *Source*: **Deploy from a branch**
3. Branch: **`main`**, папка **`/docs`** → **Save**
4. Через 1–2 минуты приложение будет тут: **https://aistben.github.io/TrackerGym3/**

На телефоне: открыть ссылку → «Поделиться / Меню» → **На экран «Домой»** — иконка как у обычного приложения, данные сохраняются локально в localStorage браузера; для онлайн-поиска и проверки штрихкода нужен интернет.
После изменений в коде: `npm run build:pages` (собирает single-file `dist/index.html` и обновляет `docs/` вместе с манифестом и иконками), закоммитить — Pages обновится сам.

## Сканер: что читается и почему иногда «не находит»

Читаются EAN-13/EAN-8/UPC-A/UPC-E, CODE-128, CODE-39, ITF-14, **QR** и **DataMatrix**
(в том числе GS1-коды «Честного знака» и GS1 Digital Link со ссылкой).

Важно понимать, что именно зашито в код:

- штрихкод на упаковке — это номер товара (GTIN), по нему приложение ищет карточку в своей базе и Open Food Facts;
- QR читается, только если внутри есть номер товара: голая цифровая строка, ссылка вида
  `https://…/01/04600494561238/10/…`, `?gtin=`/`?ean=`, GS1-код с AI `(01)` или 8–14-значное число в пути ссылки;
- QR со ссылкой на сайт производителя, кассовым чеком, акцией или Wi-Fi **не содержит БЖУ**, и приложение честно
  говорит: «нет номера товара» — это не поломка сканера;
- если товара нет в Open Food Facts (у российских товаров это часто), приложение отдельно скажет «не найден в базе»
  или «нет связи с базой» и предложит заполнить карточку вручную.

Если код не находится:

1. Нажимай **📸 Снять камерой телефона / выбрать фото** — по фото код находится надёжнее, чем по живому видео
   (разбор идёт по областям с повышенной точностью).
2. Держи код в рамке, ближе (10–20 см), без бликов и под углом, включи подсветку 🔦 в тёмном помещении.
3. Цифры под штрихкодом можно ввести вручную — поле ниже принимает и цифры, и полный текст QR (вставь из
   любого приложения-сканера).
4. Для камеры нужен HTTPS или localhost: на http-адресе живое видео не запустится, но фото и ручной ввод работают.
5. Штрихкода нет совсем (развесное, домашнее, кафе) — жми **«+ Создать свой продукт»** и впиши название и БЖУ вручную.
6. Если после скана показан **не тот продукт**, открой **«❌ Не тот продукт? Найти по названию»**, введи название и бренд с упаковки и выбери подходящий вариант Open Food Facts. Карточка сразу сохранится в базу; при необходимости кнопка **«Обновить данные по штрихкоду»** заново проверит найденную карточку онлайн.

### Что находится без интернета

В комплекте с приложением идёт база на 232 продукта, и у части брендовых позиций указан **проверенный штрихкод** — такой товар подставляется сразу при скане, даже в магазине без связи. Первыми в этот список попали частые покупки в «Магните»: соусы «Махеевъ» (Сырный, Цезарь, Сливочно-чесночный, Сметанный с грибами, Тар-тар, Бургер, кетчупы, майонез), сырные соусы Heinz, Слобода, Astoria, Mr. Ricco, Pikador, зефир «Бело-розовый» Сокол с ароматом ванили и малины и бакалея с той же полки. EAN-13 зефира — **4603513006871**; гречка Увелка ядрица 800 г — **4607016240893**; гречка «Магнит» 1 сорт — **4650259570050**; рис Националь круглозёрный — **4600935000036**; рис Мистраль басмати — **4601916000342**; спагетти Макфа — **4601780000189**; перья Шебекинские — **4607001850090**. Маркировочный GTIN-14 с ведущим нулём сводится к тому же коду, поэтому QR/DataMatrix-код с этим GTIN найдётся локально. Если сканер прихватил срок годности «120» дней с этикетки, хвост отбрасывается. Поиск по названию также находит продукт без интернета, в том числе СТМ «Магнит» (гречка 1 сорт, рис круглозёрный, спагетти).

Чего в базе нет — то приложение честно ищет в Open Food Facts. Если там лежит карточка без БЖУ (у российских товаров это обычное дело: название есть, цифр нет), приложение открывает форму с подставленным названием и просит вписать данные с упаковки — в следующий раз этот штрихкод найдётся уже мгновенно, из своей базы.

Онлайн-поиск пищевой ценности идёт по базе **Open Food Facts**, а не по произвольным сайтам: на них обычно нельзя надёжно автоматически извлечь БЖУ из браузера. Полнота пользовательской базы зависит от того, добавлял ли кто-то продукт и корректные ли данные указаны на сайте.

## Запуск

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # dist/index.html (single-file сборка)
npm test         # автотесты: разбор штрихкодов, детектор, поиск и чтение QR/DataMatrix с картинок
npm run build:pages  # сборка для GitHub Pages (docs/index.html + иконки и манифест)
npm run typecheck
```

Для работы камеры нужен HTTPS или localhost.
