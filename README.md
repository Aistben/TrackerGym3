# 🥗 Nutri — трекер питания, БЖУ и веса

Приложение для похудения / поддержания / набора массы. React + TypeScript + Vite + Tailwind.

## Что умеет

- **Цель и расчёт нормы.** Пол, возраст, рост, стартовый и целевой вес, активность → BMR (Миффлин–Сан Жеор), TDEE и дневная норма калорий с учётом выбранного темпа (кг/нед). БЖУ считаются автоматически (белок по кг веса, жиры 30% калорий, остальное — углеводы).
- **Дневник по дням.** Приёмы пищи со **своим временем** (Завтрак 08:30, Обед 13:30 и т.д.), продукты с граммовкой, кольцо калорий и полосы БЖУ.
- **Копирование приёмов пищи.** Кнопка «→ завтра» в один тап, а также копирование/перенос на любую дату и дублирование внутри дня.
- **Скан штрихкода — основной путь.** Плавающая иконка «Сканировать» (та, что остаётся на экране при скролле) сначала спрашивает **куда добавить**: день (сегодня / вчера / завтра / любой из календаря) и конкретную строку-приём с её временем — либо предлагает создать новый приём с нужным временем. После выбора открывается сканер (нативный BarcodeDetector + ZXing): штрихкод, QR или DataMatrix с номером товара → карточка подставляется из своей базы или Open Food Facts. Если отсканировать пришлось на другой день, дневник сам переключается на него — товар сразу видно. Не нашлось — открывается ручная карточка с уже подставленным кодом.
- **Оценка БЖУ по названию.** Нечего сканировать — блюдо в кафе, домашняя еда, что-то «на глаз»? Введи название («шаурма», «борщ», «творожная запеканка»): приложение подберёт похожее блюдо из справочника типовых блюд (~120 позиций) или посчитает медиану по похожим продуктам Open Food Facts и подставит примерные калории и БЖУ с пометкой «ориентировочно». Работает офлайн по справочнику, интернет нужен только для второго варианта.
- **Поиск по названию.** Недавние и своя база + онлайн-поиск Open Food Facts; найденное сохраняется в базу. Если штрихкод привёл не к тому соусу, в карточке порции можно обновить данные по коду или найти продукт по названию с упаковки — онлайн-карточка сохранится в базу и заменит старую запись с тем же штрихкодом.
- **База продуктов.** ~65 предустановленных продуктов + свои и найденные онлайн; поиск, редактирование, удаление. Если в онлайн-карточке есть БЖУ, но нет калорий, приложение рассчитывает ккал из белков, жиров и углеводов.
- **БЖУ считаются автоматически** (белок по весу, жиры 30% калорий, остаток — углеводы); тонкая подстройка — слайдером «Ручная корректировка» калорий.
- **Замок и возврат нормы.** Ручную корректировку калорий можно зафиксировать замком 🔒 — случайное касание слайдера её больше не сдвинет, а вертикальный скролл страницы проходит сквозь слайдер и значение не задевает. Стрелка ↩ стоит вплотную к замку и возвращает прежнее значение (например, было +300, случайно уехало на +500 — одно нажатие возвращает +300); история хранит до 20 шагов и сохраняется вместе с профилем, так что возврат работает даже после закрытия настроек или перезагрузки приложения.
- **Компактные настройки.** Активность выбирается выпадающим списком с подсказками, поля «Возраст/Рост/Вес» — компактные, кнопки данных (сохранить/загрузить/сбросить) в одну строку.
- **Графики, которые растут вместе с записями.** Вес: факт против плановой траектории от стартового веса + линия цели и прогноз срока. Калории по дням с линией нормы. БЖУ по дням (stacked). Диапазон — выпадающий список: неделя (вес по дням), 2 недели, месяц, 3 месяца, год.
- **Данные локально** (localStorage), есть экспорт/импорт JSON.

## Деплой на Vercel (рекомендуется)

Репозиторий уже настроен: `vercel.json` (framework `vite`, build `npm run build`, output `dist`, SPA-rewrites, `Permissions-Policy: camera=(self)`).

1. Открыть **https://vercel.com/new** и войти через GitHub
2. **Import** репозитория `Aistben/TrackerGym3` (при первом разе — Add GitHub Account / Configure и дать доступ к репо)
3. Настройки подставятся сами из `vercel.json` → **Deploy**
4. Через ~1 минуту будет адрес вида `https://tracker-gym3.vercel.app`

Какая ветка уходит в прод:
- слить PR `arena/01a0f7b4-trackergym3 → main` — прод собирается с `main`;
- либо **Project → Settings → Git → Production Branch** поставить `arena/01a0f7b4-trackergym3`.

Каждый пуш в ветку = автоматический новый деплой, плюс preview-ссылка на каждый PR.

## Открыть с телефона (постоянная ссылка)

В репозитории лежит готовая однофайловая сборка `docs/index.html`. Чтобы получить постоянный HTTPS-адрес:

1. GitHub → репозиторий → **Settings → Pages**
2. *Source*: **Deploy from a branch**
3. Branch: **`arena/01a0f7b4-trackergym3`**, папка **`/docs`** → **Save**
4. Через 1–2 минуты приложение будет тут: **https://aistben.github.io/TrackerGym3/**

На телефоне: открыть ссылку → «Поделиться / Меню» → **На экран «Домой»** — иконка как у обычного приложения, данные сохраняются локально в localStorage браузера; для онлайн-поиска и проверки штрихкода нужен интернет (оценка по справочнику типовых блюд работает офлайн).
После изменений в коде: `npm run build && cp dist/index.html docs/index.html`, закоммитить — Pages обновится сам.

## Сканер: что читается и почему иногда «не находит»

Читаются EAN-13/EAN-8/UPC-A/UPC-E, CODE-128, CODE-39, ITF-14, **QR** и **DataMatrix**
(в том числе GS1-коды «Честного знака» и GS1 Digital Link со ссылкой).

Важно понимать, что именно зашито в код:

- штрихкод на упаковке — это номер товара (GTIN), по нему приложение ищет карточку в своей базе и Open Food Facts;
- QR читается, только если внутри есть номер товара: голая цифровая строка, ссылка вида
  `https://…/01/04600494561238/10/…`, `?gtin=`/`?ean=`, GS1-код с AI `(01)` или 8–14-значное число в пути ссылки;
- QR со ссылкой на сайт производителя, кассовым чеком, акцией или Wi-Fi **не содержит БЖУ**, и приложение честно
  говорит: «нет номера товара» — это не поломка сканера;
- если товара нет в Open Food Facts (у российских товаров это часто), приложение отдельно скажет «не найден в базе»
  или «нет связи с базой» и предложит заполнить карточку вручную — либо оценить БЖУ по названию.

Если код не находится:

1. Нажимай **📸 Снять камерой телефона / выбрать фото** — по фото код находится надёжнее, чем по живому видео
   (разбор идёт по областям с повышенной точностью).
2. Держи код в рамке, ближе (10–20 см), без бликов и под углом, включи подсветку 🔦 в тёмном помещении.
3. Цифры под штрихкодом можно ввести вручную — поле ниже принимает и цифры, и полный текст QR (вставь из
   любого приложения-сканера).
4. Для камеры нужен HTTPS или localhost: на http-адресе живое видео не запустится, но фото и ручной ввод работают.
5. Штрихкода нет совсем (развесное, домашнее, кафе) — жми **«🤔 Не знаю БЖУ — оценить по названию»** и введи название блюда.
6. Если после скана показан **не тот продукт**, открой **«❌ Не тот продукт? Найти по названию»**, введи название и бренд с упаковки и выбери подходящий вариант Open Food Facts. Карточка сразу сохранится в базу; при необходимости кнопка **«Обновить данные по штрихкоду»** заново проверит найденную карточку онлайн.

Онлайн-поиск пищевой ценности идёт по базе **Open Food Facts**, а не по произвольным сайтам: на них обычно нельзя надёжно автоматически извлечь БЖУ из браузера. Полнота пользовательской базы зависит от того, добавлял ли кто-то продукт и корректные ли данные указаны на сайте.

## Запуск

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # dist/index.html (single-file сборка)
npm test         # автотесты: разбор штрихкодов, детектор, поиск и чтение QR/DataMatrix с картинок
npm run typecheck
```

Для работы камеры нужен HTTPS или localhost.
